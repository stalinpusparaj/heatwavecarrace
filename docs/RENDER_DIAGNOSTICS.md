# Local rendering diagnostics

Open the game with `?debug` in the URL (for example `http://localhost:4173/?debug`) to show the DEBUG button; players never see it. Open DEBUG, start a solo mission, then select **COMPARE SAME SCENE · 30 SEC**. Four sequential segments use Normal / Pixel / Pixel / Normal ordering. Each segment has 1.5 seconds warmup plus approximately 6 seconds measurement. The simulation is frozen at the same mission snapshot; no results, progress or rewards are produced by the comparison. Effects remain present at the same ages. It uses fixed Eco quality and its 30 FPS draw cap for both resolutions. Original resolution/profile are restored after completion or cancellation. Backgrounding or changing viewport invalidates the run. Co-op is excluded because a live server match cannot be frozen safely.

The pixel canvas uses a 240-pixel short edge with nearest-neighbor CSS scaling; UI stays at normal resolution. This is a rendering-resolution experiment, not a completed pixel-art conversion. Portrait aspect ratio determines actual height.

Report metrics: rAF interval mean/p95, render submission CPU mean/p95 (painted samples only), JavaScript callback work mean, number of intervals above 50 ms, samples and canvas dimensions. JavaScript timing excludes deferred raster/GPU/compositor completion. rAF intervals describe callback scheduling, not the 30 FPS intentional draw cadence. Long rAF frames must not be mistaken for the deliberate draw cap. CPU values are subject to timer precision and browser scheduling.

Live telemetry records up to 600 samples only while DEBUG is open. Frozen comparison excludes AI/physics, HUD settlement, networking and player interaction. Use live telemetry while playing to investigate those costs separately. Nothing is sent to analytics; report JSON is available locally in the panel. No retention, low-end phone performance or GPU-speedup claim follows from desktop browser measurements.

For an affected Android phone, repeat the same four-segment capture with the same mission, viewport, foreground state and thermal conditions. Compare repeated captures and frame p95, not just a single render mean. Keep visual style unchanged unless measured gains justify the tradeoff. If render CPU is already substantially below 1 ms and scheduling stays stable, reducing art further is not established as a solution; inspect WebView/GPU and full gameplay traces next.

## Captured browser result

19 October 2026, current desktop in-app browser, Desert County level 3, viewport held constant. Raw local report: `render-comparison-browser.json`. Normal canvas 494×606; pixel canvas 240×294. Four segments had 720–722 rAF samples each, and 172–175 rendered frames. Normal render CPU means were 0.195 and 0.177 ms; pixel means were 0.182 and 0.198 ms. Pooled-by-segment means are approximately 0.186 ms normal and 0.190 ms pixel (about 2% slower, within small timing variation). All segments had 0.400 ms render p95, roughly 8.33 ms rAF interval and 0 intervals over 50 ms. There is no demonstrated speedup and no justification from this capture to replace the complete art style for performance. This is not an Android or end-to-end gameplay benchmark.
